# Jev routing and triage pilot — Codex GPT-6 trio (advisory only)

Status: opt-in benchmark CLI, not connected to the Hermes agent loop, Kanban dispatcher, Mission Control, or any profile model config. It never selects or changes a running model, assignee, approval, or safety rule. This PR follows merged pilot PR #78; it does not remove the fleet's non-Codex outage recovery chain.

## Run and disable

Run `python3 scripts/jev_routing_pilot.py tests/jev_historical_summaries.json` for a network-free policy baseline. Only `--live` performs network requests. It requires `TYPESAFE_API_KEY` in the process environment for Jev and a usable Hermes Codex OAuth account under that process's `HERMES_HOME` for live account-scoped catalog discovery. The script does not copy credentials between profiles; an unauthenticated profile fails closed with no eligible candidates. Omit `--live` (or stop invoking the script) to disable calls. Never submit raw private task descriptions: fixture summaries were manually abstracted.

## Exact data boundary and policy

The only inference candidates, hard-coded in `CODEX_CANDIDATES`, are `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna` under `openai-codex`. In live mode, a fresh account-scoped Codex `/backend-api/codex/models` response, authenticated with the account header, is intersected with this trio. It does **not** use `get_codex_model_ids`: that picker can augment a real catalog with cached and forward-compatible synthetic IDs. If catalog discovery fails or the fallback model is missing, no route or Jev call is made. Offline fixture `available_models` is a simulation, not live entitlement evidence; arbitrary fixture `candidates` cannot add inference choices. TypeSafe `jev-1.13.0` is the classifier API, not a Codex inference candidate.

For eligible fixtures, one `POST https://api.typesafe.ai/v1/systemone` sends `model: jev-1.13.0`, `state: {task: deidentified_summary}` plus `current_model` only if present in the verified catalog intersection. `questions.model_route` is a choice over exactly the available subset of the trio. `questions.task_triage` contains caller-provided teams when present, independently of inference. `questions.escalate` is yes/no only when a current model is available. No task ID, original body, session history, user identity, approval details, or Codex credential enters the TypeSafe payload; TypeSafe's bearer token is an HTTPS header. The script does not auto-redact arbitrary summaries: curation is the caller's responsibility.

A safety/approval hold returns no route even if a user pin is valid. A valid user pin skips Jev; an unavailable pin or fallback returns no route. Offline mode, absent TypeSafe credential, timeout, HTTP error, malformed response, or route confidence below 0.80 uses the available deterministic fallback. Invalid live summary/triage input fails closed with no route. All choices remain recommendations, never executable control flow. `current_model` and escalation advice do not switch models mid-task.

Output includes route probabilities/confidence, threshold-accepted triage/escalation advice, reason, latency, input tokens and estimated TypeSafe cost (`input_tokens × $0.042 / 1,000,000`, pricing reference 2026-09-24). This is not Codex inference cost or a billing receipt. Codex prices, model execution latency and answer quality were **not measured**; the rubric cannot claim one of the trio is cheaper or better from this evidence.

## Labeled evaluation and rollout gate

The ten de-identified prior task summaries now carry *retrospective heuristic labels* for candidate routing (Astra: broad/cross-component or high-risk integration; Sol: moderate configuration/integration; Luna: bounded fix). They are a proxy rubric assigned from titles, **not observed best-model outcomes**, and are not independent blinded adjudication. Historical board runs contained no model override gold labels. Triage labels are historical assignees. Any reported `model_accuracy` is agreement with this rubric, not inference quality. This tiny biased sample is unsuitable for threshold tuning or rollout.

Live advisory probe (2026-09-24, ten curated cases, account catalog returned all three): 3/10 routing-label agreement *after fallback*, 3/10 accepted-correct triage, mean TypeSafe latency 316.02 ms, TypeSafe input-cost estimate $0.00019929. All ten route confidences were 0.13–0.39, below 0.80, so all ten routes fell back to Sol. A second diagnostic run likewise chose the fallback on all ten; do not interpret the 3/10 as genuine model preference accuracy. Offline baseline has no calls, no cost and 3/10 fallback-label agreement. No actual Codex model responses, latency or charges were compared.

Decision: **do not enable live automatic routing**. Before proposing integration: adjudicate a larger held-out set with real best-model labels and per-model execution quality/latency/cost; verify account availability for each target profile; review payload privacy; measure failure modes and confidence calibration; obtain explicit approval gate. The tests run with `HERMES_PYTHON=/home/solo/.hermes/hermes-agent/venv/bin/python scripts/run_tests.sh tests/test_jev_routing_pilot.py -q` without credentials. No runtime deployment is required.
